# Data source documentation

One directory per registered pipeline source (`src/data/sources/registry.py`),
each with a `README.md` describing every stage that source stores durable
output for: what it is, where it lands on disk (see
`src/data/sources/layout.py`), its schema/variables, and known
data-quality caveats found in the code/config comments.

This index and the per-source pages are generated by reading code and
`orchestration/configs/data.yaml` only — nothing here was derived by opening
actual data files. Where a fact can only be confirmed by inspecting a live
run's output (real date coverage achieved, actual row/tile counts, empirically
observed value ranges, disk sizes), the page says so explicitly with a
`**TODO (needs live data):**` marker instead of guessing. Treat those as open
items, not gaps in the writing.

Related, pre-existing docs this index doesn't replace:
- `docs/design/09-integrated-pipeline.md` — the pipeline migration design doc
  (per-source STEPS/REQUIRES table, path-mapping table).
- `docs/design/07a-modis-band-reference.md` — the one pre-existing per-variable
  schema reference, MODIS-only.
- `orchestration/configs/data.yaml` — source configuration, including each
  source's `verification:` block (expected variables + physical value range).

## Layout note

Every source's path template follows one stage-name-first physical tree:
`raw/<data_path>`, `prepared/<data_path>`, `grid/<grid_id>/<family>.zarr` —
see `src/data/sources/layout.py`.
